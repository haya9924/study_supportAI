## 1. リポジトリ構成方針

**方針：同一リポジトリ内（`study_supportAI`）で旧アプリとは完全に別の新構成（クリーンルーム）として再構築する。**
（※初期に提示した「既存 backend/frontend を拡張する案」は、この方針決定により却下・上書き）

### 設計方針

- API → application → domain → infra の依存方向を一方向にする（旧アプリのようにルータへ直書きしない）
- ガイドの学習科学ルールは domain 層にハードコードし、単体テスト可能にする（分散学習間隔・3つの箱・量ベース計画など）
- AI は `application/ai_service.py` に集約：問題生成・採点 ＋ **記憶術提案**（イメージ／ストーリー／場所法）＋ **プラン提案**（テスト逆算・週間計画の下書き）
- 単一ユーザー・PCブラウザ前提：認証は簡易（APIキーはサーバー側設定のみ）、データはSQLite単一ファイル

### データモデル

- `Card`（q/a・形式・FSRS状態・箱・記憶術メモ）
- `StudyLog`（モード・結果・誤答理由・所要時間）→ セルフモニタリングの元データ
- `CornellNote`（本文・キーワード・まとめ）
- `Goal`（短期／中期／長期）・`Exam`（テスト日・目標点）・`DailyPlan`（量指定タスク）
- `PomodoroSession`・`ChecklistProgress`

## 2. マスタリー・ワールドマップ 概念設計（最新版）

学力の式「理解 × 定着 × 点数化」を、ゲーム的な**ワールドマップ**として表現する設計。
以下は初期案（v1）に対する4つの検討課題の決定事項を反映した最終版。

| 検討課題 | 決定事項 |
|---|---|
| ノード粒度 | **2日で1ノード消化**できるサイズ（単元より小さく、単一概念より大きい「小トピック」） |
| 診断の再実施 | 計画策定時 ＋ **ボス前にも軽い診断**（デフォルトON、設定でオフ可） |
| スキップの自由度 | 緑ノードでも「実は怪しい」と自分で黄に降格してやり直せる |
| マップの見せ方 | **全容を最初から見せる**（未解放ノードはシルエット表示） |

### 2-1. ノードの内部設計（2日リズム）

1ノード＝2日分の学習量。「わかる → できる」をそのまま2日に分ける。

```
Day 1「わかる日」
  ① 発見 : 教材・解説を読む（インプットは最小限）
  ② 理解チェック : 基礎クイズ（短答・選択）
  ③ 「なぜ」を3つ言語化（精緻的質問）
  ④ 白紙書き出しで理解度を軽く自己確認

Day 2「できる日」
  ① 演習 : 量指定（例: 10問）
  ② 誤答処理 : なぜ間違えたか記述 → 式を見ずに解き直し
  ③ クリア判定ミニテスト（正答率基準）
  ④ クリア → 緑 / 未達 → 補強ブランチへ
```

→「2日で1ノード」がそのまま1日分のプラン配分の単位になる
（例：テストまで残り20日なら最大10ノード攻略可能、と逆算しやすい）

### 2-2. ボス前診断ゲート

合流ステージ・ボスステージの手前に診断ゲートを設置（デフォルトON）。

```
[前提ノード群] → 診断ゲート（前提ノードから混合問題を自動生成＝インターリービング診断）
                    │
       弱点なし ────┤
                    │
       弱点検出 ───→ 該当ノードを自動で黄に降格 + 補強ブランチを提示
                          ↓
                ユーザー選択: 「このまま進む」 or 「補強してから進む」
```

- ボスに挑んで大失敗する（自己効力感が下がる）前に弱点を潰せる
- 合流地点で「どの要素が欠けているか」を事前に特定できる
- 設定でオフにすると、従来の「ボスに挑む→失敗したら事後分岐」に切り替わる

### 2-3. ノードの状態と自己降格

```
[ロック] → [解放] → [進行中] → [緑: できる]
 シルエット    白       青          │
                                    ├→ [黄: 怪しい] ← ユーザーが自分で降格可能
                                    └→ SRS復習キューへ（忘れる頃に再出現）
[赤: わからない] ← 診断・ボス前ゲートの判定
[黄・赤] → 補強ブランチ → 緑に復帰
```

- 緑ノードでもいつでも「実は怪しい」と黄に下げてやり直せる（マップ上でノード選択→降格）
- 降格するとプランが即再計算され、再攻略がスケジュールに入る
- 黄・赤ノードはSRS復習にも自動登録される

### 2-4. ワールドマップ＝ホーム画面

- 章＝エリアゾーンで区切り、内部にノード群。合流ノードは「複数の道が集まる」特別な見た目
- ロック済みノードはシルエット表示（名前と形は見えるが内容は開けない）
  → 先の難所・合流・ボスが最初から見え、長期的モチベーションになる
- マップ上に常時表示：
  - 自分の現在位置
  - 全体進捗％（緑ノード数／全ノード）
  - デッドライン表示（例：「テストまで14日・残り7ノード・1日0.5ノード必要」→遅れたら警告）
- ゲーム感覚の演出：ノードクリアでスター（1〜3）、ボス撃破演出、継続日数バッジ、合流解放エフェクト

### 2-5. 全体フロー

```
① 初期診断（計画策定時）
   → AIが要素マップ生成 + 診断テスト → 緑/黄/赤に色分け
② プラン生成（テスト日から逆算・ノードを日割り）
③ 毎日: マップで今日のノードを攻略（Day1わかる / Day2できる）
④ 合流前: 診断ゲート（弱点あれば補強ブランチ）
⑤ ボス: 章クリア → SRS復習キューへ
⑥ 途中で「怪しい」と思ったら自己降格 → プラン再計算
```

- 補強ブランチ（要素分解／別アプローチ／暗記特化）は、ボス前ゲートの結果でも失敗後でも出現
- ブランチをクリアすると本線に再合流し、「遠回りしてでも補強した道」としてマップに履歴が残る

### 2-6. ステージ種別（v1からの詳細）

| 種別 | 内容 | 解放条件 |
|---|---|---|
| 発見ステージ | 教材を読む（最小インプット） | 前提ノードクリア |
| 基礎ステージ | 単一概念の理解確認（短答・選択） | 発見ステージ |
| 演習ステージ | 反復練習で「できる」化（量ベース） | 基礎ステージ |
| 合流ステージ | 複数要素を組み合わせる総合問題 | 前提ノードを全てクリア |
| ボスステージ | 章・単元の総仕上げ（テスト形式・時間制限） | 合流ステージ群 |
| 補強ブランチ | 失敗時に出現する代替ルート | 失敗時のみ出現 |
| 応用ステージ | 発展・他分野との連携 | ボスクリア後（任意） |

補強ブランチの3パターン：
1. **要素分解ブランチ**：合流失敗時、どの前提要素が弱点かを切り分けてミニステージ化
2. **別アプローチブランチ**：同じ内容を別の説明で（AIが教材から別切り口を生成）
3. **暗記強化ブランチ**：理解はあるが用語が覚えられない場合（見るだけ暗記→即テスト）

### 2-7. 学習科学との対応

- **アクティブリコール**：Day1白紙・Day2演習の中心
- **分散学習**：緑ノードがSRSで復習ステージとして定期的に再出現
- **精緻的質問**：Day1の「なぜ3つ」＋誤答理由の言語化
- **インターリービング**：診断ゲート・合流ノードで要素を混ぜて出題
- **3つの箱**：緑／黄／赤が箱①②③に対応、自己降格＝「②に戻す」
- **自己効力感**：2日で確実に1ノード＝小さな成功体験の積み上げ、量ベースで終了条件が明確

## 3. 利用者目線の学習フロー（UX観点の補足）

### 初回セットアップ（1回のみ）
1. 科目フォルダと教材を投入（PDF等はOCRで自動読取）
2. テスト日・目標点を登録
3. 学習設定（1日の新規カード数、保持率目標）を設定
→ AIがテストまでの逆算プラン下書きを生成（週ごとの量を自動割当、編集可）

### 毎日のサイクル
- ホームに「今日の学習タスク」が量で表示される
- 教材を見る（最小限のインプット）→ すぐアウトプット
  - 4モード：白紙勉強法／短答式／多選択肢／見るだけ暗記→即テスト
- 誤答は「なぜ間違えたか」を記述 →自動で3つの箱に分類
- 覚えにくい用語にはAIが記憶術（語呂・イメージ・ストーリー・場所法）を提案
- ポモドーロ（25分集中／5分休憩）を自動計測
- 学習終了後は記録が自動で統計に反映、睡眠リマインドも表示

### 復習（分散学習）
- FSRSエンジンが最適な間隔で復習キューに自動配列
- 4段階評価（もう一度／難しい／普通／簡単）を押すだけで間隔が自動調整
- 復習は科目を混ぜて出題（インターリービング）
- コーネル式ノート（右に本文・左にキーワード・下にまとめ）＋隠して思い出すボタン

### 週次サイクル
- 週末に白紙勉強法で1週間分を総点検
- 間違えた問題だけ解き直し
- AIが週間統計から来週のプランを修正提案

### テスト直前期（残り10日目安）
- 仕上げ期間へフェーズ切替を提案
  - 暗記系：一問一答＋見るだけ暗記法で集中
  - 数学・理科：間違えた問題だけ解き直し
- テスト形式の問題集で本番シミュレーション（タイマー付き）
- 前日は新規学習をせず、復習と睡眠を優先するよう案内

## 6. UIナビゲーション設計（確定版・3タブ＋マップ中心）

### 6-1. 方針

学習サイクルは**マップを軸に操作**する。学習・復習はマップのノードをクリックすることで
「次にやること」を優先順位順に表示し、ユーザーは基本的に**上からクリックするだけ**で進める。

タブは最小限の **マップ / 統計 / 設定** の3つに削減する。
（学習方式ごとのタブ（学習・復習・ノート・プランナー等）は廃止し、ノードの文脈から呼ぶ）

### 6-2. 全体レイアウト

```
┌────────────────────────────────────────────────┐
│ topbar: brand | マップ● 統計 設定 | ポモドーロ | 科目:理科 | 継続 | テーマ │
├────────────────────────────────────────────────┤
│ dash: 今日のステージ | 進捗% | テスト期限         │
├──────────┬─────────────────────────────────────┤
│ 今日やる │  ワールドマップ（Canvas 3D）          │
│ こと     │   ノードクリック→詳細パネル（右）      │
│ （常設    │   サイドバー項目クリックでノード選択＋  │
│  サイド   │   該当アクションを自動開始            │
│  バー）  │                                      │
├──────────┴─────────────────────────────────────┤
```

### 6-3. トップバー

- タブ: **マップ（active）/ 統計 / 設定**
  - 統計・設定はフェーズ7/9で実装（それまでトースト案内）
- **ポモドーロタイマー**常駐（25:00・開始/停止、モック）
- **科目スイッチャー**常駐（現在は「理科」のみ。複数科目時に拡張）
- 継続日数バッジ・テーマ切替（既存）

### 6-4. 「今日やること」常設サイドバー（左・約280px）

優先順位ロジック `buildTodayQueue()`:

```
① 期限切れ / 今日期限の復習（SRS・ノード別に件数表示）→ クリックで復習開始
② 今日のノード（today / 進行中）の Day タスク（例: 明反応 Day2 演習→クリア判定）
③ 補強が必要（黄/赤）＋ 待機中の診断ゲート
④ 解放済みで未着手（unlocked）→ Day 1 開始
⑤ 計画分の残り（期限から算出）
```

- 各項目: 番号 + 種別バッジ（復習/学習/診断/補強）+ ノード名 + 説明
- クリック → ノード選択（`centerOn`）＋詳細パネル表示＋該当アクション実行
- 上から順に1件ずつこなし、完了は「✓」でセッション内チェック → 次へ

### 6-5. 復習（SRS）の統合

- Card は所属ノードを持つ（ノードクリック →「このノードの復習カード」）
- 期限超過カードは「今日やること」の最上位にグローバル表示
- インターリービングは「今日やること」に複数ノードの復習を混ぜることで実現

### 6-6. 機能の行き先（タブ廃止分）

| 旧タブ | 行き先 |
|---|---|
| 学習（4モード） | ノードの Day タスク内 |
| 復習 | ノードクリック＋今日やること最上位 |
| ノート | ノードのアクション「コーネルを編集」 |
| プランナー | マップ上部のオーバーレイ（テスト逆算・日割り・期限） |
| 3つの箱 | 誤答の自動分類＋ノード状態（緑/黄/赤）がそのまま箱 |
